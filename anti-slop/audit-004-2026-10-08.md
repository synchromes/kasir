# Audit 004 — Kasirku

Tanggal: 8 Oktober 2026. Mode: **AFTER**, sesuai permintaan audit proyek yang sudah ada. Acuan: `AGENTS.md`, `DESIGN.md`, core `antislop`, serta companion `antislop-ui`, `antislop-human`, `antislop-layoutmobile`, `antislop-copywriting`, dan `antislop-code` yang terpasang di `C:/Users/TestAudio/.config/opencode/skills/`.

**Hasil: 21 temuan aktif — 16 HIGH, 0 MEDIUM, 5 LOW. Gate aplikasi masih FAIL.** Build, lint, dan TypeScript lulus, tetapi render halaman setelah login gagal baik pada server pengembangan maupun produksi. Browser dapat memulihkan halaman melalui render klien, sehingga tampilannya tidak selalu menunjukkan kegagalan HTTP awal.

Tidak ada perbaikan kode aplikasi dalam audit ini. Nomor di laporan ini berlaku khusus audit 004; laporan 001–003 tetap disimpan. Prioritas mengikuti tier antislop: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW. Risiko transaksi dijelaskan terpisah dari hasil visual agar prioritas ini tidak disalahartikan sebagai penilaian CVSS.

## Cakupan dan metode

- Membaca struktur App Router, komponen bersama, server actions, autentikasi, proxy, API, Prisma, alur POS/QRIS, ekspor, struk, konfigurasi, dan tes. Panduan Next.js dari versi lokal `node_modules/next/dist/docs/` digunakan sebagai acuan.
- Menjalankan aplikasi dengan database `kasir_v2` yang sudah ada; tidak menjalankan seed atau migrasi. Form dengan simulasi kegagalan jaringan diblokir sebelum POST mencapai server. Tidak membuat penjualan, pembelian, produk, pengeluaran, atau perubahan pengaturan.
- Mengunjungi 20 halaman pada desktop dan mobile: `/login`, `/`, `/pos`, `/products`, `/categories`, `/units`, `/suppliers`, `/customers`, `/purchases`, `/stock`, `/sales`, `/expenses`, `/reports`, `/notifications`, `/users`, `/settings`, `/pos/rangkuman`, `/pos/confirm`, `/sales/38`, dan `/pos/success/38`. ID 38 adalah transaksi yang sudah ada.
- Lebar yang direkam: 320, 360, 393, 412, 480, 768, 1024, 1280, dan 1440 px. Semua halaman dikunjungi pada 1440 dan 412 px; lebar lain menggunakan halaman perwakilan. Ini bukan matriks lengkap setiap halaman × setiap lebar.
- Menggunakan Edge/Chromium headless melalui Playwright. Axe memeriksa `main` pada 17 halaman; kontras teks dihitung terpisah dari warna hasil render, dengan komposit alpha/opacity. Pemeriksaan kontras otomatis tidak mencakup seluruh gradient, SVG, gambar, tooltip, dan semua state interaksi.
- Merekam 123 screenshot, JSON interaksi/aksesibilitas/layout, trace tes yang gagal, CSV hasil ekspor, dan PDF struk. Artefak berada di [evidence-004](./evidence-004/).

Login secara normal mereset counter login dan permintaan notifikasi dapat menyinkronkan peringatan stok sesuai perilaku aplikasi. Karena itu audit ini tidak mengklaim seluruh database tetap identik byte demi byte. Tidak ada mutasi data bisnis yang sengaja disubmit.

## Temuan bernomor

### 1. HIGH — Render server gagal pada layout halaman setelah login

**Aturan: R-35, R-27; C-4.** Halaman tidak memenuhi verifikasi runtime meskipun tampak pulih di browser.

`useCartBar()` memanggil `useSyncExternalStore(subscribe, getSnapshot)` tanpa argumen snapshot server. `BottomNav` menggunakan hook ini di layout bersama; menyembunyikan navigasi dengan CSS pada desktop tidak menghindari render server.

- Bukti pengembangan: 17 rute dasar setelah login menghasilkan HTTP 500 pada kunjungan awal, pada kedua profil. Console/server mencatat `Missing getServerSnapshot, which is required for server-rendered content. Will revert to client rendering.`
- Bukti produksi: setelah host autentikasi dikenali, `/`, `/pos`, `/products`, `/reports`, dan `/pos/success/38` tetap HTTP 500 dengan error yang sama. Jadi masalah ini tidak terbatas pada Fast Refresh.
- Lokasi: [cart-bar-store.ts](../components/pos/cart-bar-store.ts), baris 30; [bottom-nav.tsx](../components/bottom-nav.tsx), baris 22.
- Dampak: respons awal gagal, fallback klien, error console, dan navigasi yang tidak stabil. Dua tes regresi timeout saat login/navigasi; penyebab detail setiap timeout tetap perlu dicek dari trace.
- Arah perbaikan: sediakan snapshot server yang stabil dan cocok dengan render awal klien; verifikasi respons dokumen 200 pada dev dan produksi.
- Bukti: [browser-results.json](./evidence-004/browser-results.json), [production-results.json](./evidence-004/production-results.json), [production-auth-url.log](./evidence-004/production-auth-url.log).

### 2. HIGH — Startup produksi dengan lingkungan saat ini gagal autentikasi

**Aturan: R-35, R-26.** Build berhasil belum menghasilkan alur login produksi yang dapat dipakai.

`npm run build` lulus. Saat hasilnya dijalankan dengan `next start` tanpa override lingkungan, login menuju `/api/auth/error` HTTP 500; server mencatat `UntrustedHost`. Konfigurasi Auth.js belum memperoleh URL/kepercayaan host yang diperlukan pada lingkungan lokal ini. README juga belum menjelaskan konfigurasi autentikasi untuk startup produksi.

- Lokasi: [auth.ts](../lib/auth.ts), konfigurasi `NextAuth`; [README.md](../README.md).
- Batas kesimpulan: ini terbukti pada `next start` lokal dengan konfigurasi yang tersedia. Audit tidak memeriksa lingkungan hosting yang mungkin memasok variabel tersebut otomatis.
- Arah perbaikan: dokumentasikan dan validasi URL publik autentikasi serta konfigurasi proxy/host yang sesuai deployment. Dalam audit, `AUTH_URL=http://localhost:3000` hanya dipasang sementara pada proses pemeriksaan untuk mengisolasi temuan 1; `.env` tidak diubah.
- Bukti: [production-untrusted-host-results.json](./evidence-004/production-untrusted-host-results.json), [production.log](./evidence-004/production.log).

### 3. HIGH — Kegagalan jaringan membuat sejumlah form tertahan pada status menyimpan

**Aturan: R-26, R-27; C-4.** Form tidak memulihkan kontrol atau memberi jalan mencoba ulang saat request gagal.

POST form Kategori, Satuan, Supplier, Pelanggan, dan Pengeluaran dibatalkan sebelum dikirim. Pada kelima form, tombol tetap disabled dan berlabel `Menyimpan...`, tanpa pesan kegagalan. Login juga tetap `Memproses...` pada simulasi request autentikasi gagal. Handler mengatur `loading=true` lalu melakukan `await` tanpa `catch/finally`; penolakan promise melewati reset loading.

- Lokasi: [simple-crud.tsx](../components/simple-crud.tsx), baris 93; [customers.tsx](../components/customers.tsx), baris 67; [expenses.tsx](../components/expenses.tsx), baris 67; [login-form.tsx](../components/login-form.tsx), baris 13. [purchase-form.tsx](../components/purchase-form.tsx), baris 51, memiliki pola serupa secara statis; kegagalan submit pembelian tidak direproduksi.
- Pembanding: form Produk dan Pengguna menangkap kegagalan dan mengaktifkan tombol kembali pada probe yang sama.
- Arah perbaikan: pulihkan loading pada semua jalur, tampilkan pesan kegagalan yang dapat diumumkan pembaca layar, pertahankan input, dan beri retry.
- Bukti: [interaction-results.json](./evidence-004/interaction-results.json), screenshot `interaction-save-failure-*.png` dan `interaction-login-network-failure.png`.

### 4. HIGH — Keranjang akun lama tampil setelah berganti akun

**Aturan: R-27, R-26; C-4.** State pesanan tidak mengikuti identitas toko yang sedang aktif.

Dalam tab/browser yang sama, admin menambahkan Coca Cola 390ml Rp5.500, logout, lalu login sebagai kasir. Katalog akun kasir kosong, tetapi bar keranjang tetap menampilkan `1 item · Rp5.500`. Item dan `customerId` akun sebelumnya masih tersimpan. Kunci `kasir-cart`/`kasir-pending-payment` tidak memakai owner; logout tidak membersihkannya, dan restore tidak memeriksa owner atau katalog aktif.

- Lokasi: [storage.ts](../lib/storage.ts), baris 4–5; [use-pos-order.ts](../components/pos/use-pos-order.ts), restore baris 90 dan penyimpanan baris 119; [sidebar.tsx](../components/sidebar.tsx), baris 77.
- Batas kesimpulan: server checkout memeriksa `ownerId` produk. Audit ini tidak menemukan atau membuktikan penjualan lintas toko yang berhasil. Yang terbukti adalah bocornya state keranjang di browser serta pesanan yang tidak cocok dengan akun aktif.
- Arah perbaikan: pisahkan state per owner, bersihkan state saat keluar/berganti akun, dan validasi data yang dipulihkan.
- Bukti: check `cart-after-account-switch` dalam [accessibility-results.json](./evidence-004/accessibility-results.json), [screenshot](./evidence-004/accessibility-cart-after-account-switch.png).

### 5. HIGH — Kunci idempotensi checkout berubah setelah refresh

**Aturan: R-26, R-27; C-4.** Retry pesanan yang sama tidak memiliki identitas transaksi yang bertahan saat halaman dipulihkan.

Dua checkout dengan keranjang identik diblokir sebelum mencapai server, dipisahkan oleh refresh. Payload pertama memakai `saleKey` `7c34571d-be50-4997-913c-b1a503bde0f7`, payload kedua `61ead10c-6fb1-4539-a1df-168ae90c2502`. Hook membuat kunci baru saat mount/perubahan cart; payload cart yang disimpan tidak berisi kunci tersebut. Konfirmasi QRIS juga membuat UUID baru per mount dan tidak menyimpannya dalam pending payment.

- Lokasi: [use-pos-order.ts](../components/pos/use-pos-order.ts), baris 39–42 dan 120; [confirm.tsx](../components/pos/confirm.tsx), baris 68.
- Dampak yang diinferensikan: bila transaksi pertama sudah commit tetapi respons hilang, refresh lalu retry dapat melewati dedupe dan membuat penjualan kedua. Audit membuktikan perubahan kunci, bukan transaksi/charge ganda aktual.
- Arah perbaikan: simpan identitas transaksi bersama state pesanan/pending, pertahankan selama penyelesaian atau retry transaksi tersebut, dan ganti secara eksplisit saat memulai transaksi baru.
- Bukti: check `checkout-key-after-reload` dalam [accessibility-results.json](./evidence-004/accessibility-results.json).

### 6. HIGH — Retry transaksi yang sudah commit masih divalidasi terhadap stok yang telah berkurang

**Aturan: R-26, R-27; C-4.** Hasil transaksi sebelumnya dapat dilaporkan sebagai kegagalan saat retry.

`checkout()` memeriksa produk aktif/stok sebelum mencari `saleKey` yang sudah tersimpan. Jika penjualan pertama menghabiskan stok dan responsnya hilang, retry dengan kunci yang sama berhenti pada `Stok ... tidak mencukupi`, sebelum menemukan penjualan yang sudah berhasil.

- Lokasi: [actions.ts](../lib/actions.ts), validasi stok baris 95–98, lookup idempotensi baris 144–147.
- Bukti: action yang ada dijalankan dengan stub database terisolasi yang memiliki penjualan sebelumnya dan stok 0. Hasil berupa error stok; jumlah lookup penjualan **0**. Probe tidak terhubung ke MySQL dan bukan pengujian transaksi database nyata.
- Arah perbaikan: selesaikan pencarian hasil idempoten milik owner sebelum validasi kondisi stok/poin yang berubah akibat transaksi tersebut; tetap pertahankan dedupe atomik untuk request serentak.
- Bukti: [server-retry-results.json](./evidence-004/server-retry-results.json), reproduksi [audit-server-retry.mjs](./evidence-004/audit-server-retry.mjs).

## Catatan teknis dan batas pemeriksaan

- Guard owner pada query/actions, validasi harga checkout dari DB, guarded decrement stok/poin, transaksi Prisma, pembatasan gambar server, dan role khusus `/users` sudah ada. Temuan keranjang tidak membatalkan keberadaan guard server ini. Audit tidak mengklaim sistem lolos pentest.
- `qris-dinamis/` adalah proyek Vite terpisah dengan lisensi MIT, dikecualikan dari type check/lint aplikasi utama. Sumbernya ditinjau sebagai proyek pendamping; dependensi/runtime Vite tidak dijalankan. Alur QRIS terintegrasi aplikasi utama dibaca, tetapi tidak melakukan pembayaran merchant nyata.
- README masih memuat boilerplate create-next-app dan menyebut Geist, sementara aplikasi memakai Inter. Petunjuk setup DB, env, migrasi, dan produksi perlu dibahas saat pekerjaan dokumentasi disetujui; tidak ada perubahan dokumentasi aplikasi dalam audit ini.
- CSV sekarang meng-escape kutip tetapi tidak memiliki perlakuan khusus untuk string yang dapat dibaca spreadsheet sebagai formula. Tidak diuji di Excel/LibreOffice dan tidak didaftarkan sebagai exploit terbukti. Pertimbangkan pemeriksaan terpisah jika file berasal dari input pihak lain dan akan dibuka dalam spreadsheet.
- Dialog konfirmasi generik sengaja memfokuskan tombol `Hapus` saat dibuka, terbukti dalam `delete-confirm-focus`. Ini meningkatkan kecepatan Enter untuk aksi destruktif; rekomendasi usability adalah fokus awal yang lebih aman, tetapi tidak dicatat sebagai pelanggaran keyboard terpisah karena kontrol tersebut memang dapat dioperasikan.
- Tidak menguji printer fisik, kamera nyata, perangkat layar sentuh/keyboard virtual nyata, Safari/WebKit, pembaca layar langsung, seluruh reduced-motion, skala data besar, race transaksi di MySQL, restore backup, atau lingkungan deployment eksternal.
- Dev mencatat beberapa peringatan ukuran chart 0 selama render/rehydration. Screenshot chart yang masih beranimasi tidak dianggap bukti grafik permanen kosong.
